#### 0.2.0

**Breaking.** The node is now v1-native. Every call it makes targets Roam's `/v1`
surface; the only remaining `/v0` calls are the two webhook subscriptions whose
events have no dot-named equivalent in Roam's registry.

- **Breaking:** The **Transcript** resource was removed. v1 keys transcripts,
  summaries, and prompts on the *meeting*, not on a standalone transcript ID, so
  its three operations moved onto the **Meeting** resource: List Transcripts →
  **List Meetings** (`/v1/meeting.list`), Get Transcript Info → **Get
  Transcript** (`/v1/meeting.transcript`), Prompt Transcript → **Prompt Meeting**
  (`/v1/meeting.prompt`). They take a meeting ID, not a v0 transcript ID.
  Workflows still set to the old resource now fail with that migration message
  instead of silently emitting nothing.
- **Breaking:** Send Message posts to `/v1/chat.post` with a `groupId`. It
  previously used the deprecated `/v1/chat.sendMessage` for text and
  `/v0/chat.post` for Block Kit — two API generations in one node — and sent the
  v0 tagged `chat`/`recipients` fields, which `/v1` rejects.
- **Security:** The Roam Trigger verifies the Standard Webhooks signature
  (`webhook-id` / `webhook-timestamp` / `webhook-signature`) on every delivery,
  with a 5-minute replay window and a timing-safe comparison. Set **Webhook
  Signing Secret** on the Roam API credential to enable it; the value is shown
  next to the API key in Roam Administration > Developer. A delivery that fails
  verification gets a 401 and does not start the workflow. Verification is
  skipped when the field is empty, so existing workflows keep running until it is
  filled in.
- **New trigger event:** **New Chat Message** (`chat.message`), with server-side
  filtering by chat type (DM/group) and by mentions. This is the first "new
  message in Roam" trigger in the node.
- **New trigger event:** **Meeting Ended** (`meeting.ended`), optionally filtered
  to meetings that have a video recording. It supplies the meeting IDs the new
  Meeting operations take.
- **Fix:** Webhook teardown POSTs `/v1/webhook.unsubscribe` with a JSON `{ id }`
  body, and the stored subscription is cleared afterwards.
- **Change:** v1 webhook deliveries are unwrapped from the
  `{ type, eventId, timestamp, apiVersion, data }` envelope, with the envelope's
  metadata (including the retry-stable `eventId`) merged onto the output item.
  Bare v0 payloads pass through unchanged.
- **Change:** `Roam-Version` moves to `2026-07-07`, and v1 subscriptions send an
  explicit `apiVersion` pin so the frozen delivery shape follows this release
  rather than the API key's account default.
- **Change:** Credential test hits `/v1/token.info`; the group picker reads
  `/v1/group.list`.
- **Infra:** Added an automated test suite (vitest, 83 tests) covering signature
  verification, envelope unwrapping, webhook subscribe/unsubscribe routing,
  request construction for every operation, and error mapping. CI now runs it.
  The package previously had zero automated tests.
- **Infra:** Repaired `package-lock.json`, which was out of sync with
  `package.json` and made `npm ci` — and therefore CI — fail.
